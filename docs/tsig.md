# TSIG

`dns.tsig` implements RFC 8945 transaction authentication without owning I/O, clocks, or key storage.

## Ownership

A `dns.tsig.auth.Key` borrows both its secret and the caller-owned wire-name storage:

```zig
var key_name: [dns.Name.max_wire_len]u8 = undefined;
const key = try dns.tsig.auth.Key.init(
    "transfer-key.example",
    secret_bytes,
    &key_name,
);
```

`Key.init` selects HMAC-SHA256. `Key.initWithAlgorithm` can select HMAC-SHA1 for compatibility. The library never copies a secret into persistent key storage. Temporary HMAC state and returned `Mac` storage are explicitly zeroized where practical; callers remain responsible for the lifetime and zeroization policy of `secret_bytes`.

## Sign a request

```zig
var mac = try dns.tsig.auth.signBuilder(&builder, key, .{
    .time_signed = now,
});
defer mac.deinit();

const wire = try builder.finish();
```

Time is always injected by the caller. `signBuilder` hashes the unsigned DNS message and appends TSIG transactionally. `original_id` can be supplied when a forwarding path rewrites the DNS header ID; the substituted Original ID is then used both in TSIG RDATA and the MAC input.

MAC truncation is explicit through `mac_len`. Generated truncation below RFC 8945's protocol minimum is rejected.

## Verify a request or first response

Run structural validation first so TSIG placement, uniqueness, RDATA bounds, and response-only field semantics have already been checked:

```zig
const msg = try dns.Message.init(packet);
const strict = try dns.validate.messageStrict(msg, .{});
const signed = strict.tsig orelse return error.MissingTsig;

try dns.tsig.auth.verify(msg, signed, key, .{
    .now = now,
});
```

For a response to a signed request, pass the already validated request MAC exactly as received:

```zig
try dns.tsig.auth.verify(response, response_tsig, key, .{
    .now = now,
    .request_mac = request_tsig.mac,
});
```

Verification order follows RFC 8945: key, MAC, time, then local truncation policy. A local floor can be injected with `VerifyOptions.truncation`; it never weakens the protocol minimum.

The main authentication failures are deliberately distinct: `BadKey`, `BadSignature`, `BadTime`, `BadTruncation`, and structural `InvalidMacLength`.

## BADKEY, BADSIG, BADTIME, and BADTRUNC

`dns.tsig.ErrorCode` exposes the RFC values. RFC 8945 requires `BADKEY` and `BADSIG` responses to use an empty MAC; `auth.sign`/`signBuilder` therefore reject attempts to sign those errors with `UnsignedErrorRequired`. The low-level `tsig.record` builder remains available for constructing the required unsigned error RR. Signed `BADTIME` and `BADTRUNC` responses can use normal `signBuilder` with the validated request MAC.

For BADTIME, use the helpers rather than constructing the six-octet server timestamp manually:

```zig
var other: [6]u8 = undefined;
const server_time = try dns.tsig.record.badTimeOtherData(server_now, &other);

var response_mac = try dns.tsig.auth.signBuilder(&response_builder, key, .{
    .time_signed = request_tsig.time_signed,
    .fudge = request_tsig.fudge,
    .request_mac = request_tsig.mac,
    .error_code = .bad_time,
    .other_data = server_time,
});
defer response_mac.deinit();
```

After parsing, `Record.badTimeServerTime()` returns the bounded 48-bit server time.

## Multi-message responses

`dns.tsig.auth.Chain` implements the RFC 8945 continuation-MAC state needed by transfers and other multi-message responses. Its persistent state is fixed-size and independent of transfer length.

```zig
var chain = try dns.tsig.auth.Chain.init(key, first_response_mac, first_time);
defer chain.deinit();

var mac = try chain.signBuilder(&next_builder, .{
    .time_signed = next_time,
});
defer mac.deinit();
```

New senders should sign every response message. For compatibility, a receiver can `absorbUnsigned()` intermediary DNS messages; the implementation caps the count at the RFC-required compatibility limit of 99 before a signed checkpoint is required.

`Chain.verifySigned` commits state only after successful authentication. A failed checkpoint leaves the prior chain state unchanged.

## Interoperability

The optional gate

```bash
zig build interop-tsig
```

validates a request, first response, and continuation TSIG generated by Zig against dnspython.
